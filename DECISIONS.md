# DECISIONS.md — Практическая работа №5 (вариант 5)

## Решение 1. Все пороги и нормы — именованные константы одного класса

`DAYS_COUNT = 5`, `MIN_HOURS = 0`, `MAX_HOURS = 30`, `DAILY_NORM = 8`, `WEEKLY_NORM = 40`
объявлены как `private static final` в `TimesheetAnalyzer` и нигде больше не дублируются.
Индивидуальный вариант 5 («верхняя граница часов», параметр 30) сводится к одной строке `MAX_HOURS = 30`.
`Main` и `SelfCheck` порогов не знают: `Main` только печатает результат, `SelfCheck` проверяет поведение.
Отвергнутая альтернатива — передавать пороги в конструктор: для текущей задачи это лишняя гибкость.

## Решение 2. Ошибки — исключение `TimesheetFormatException` с полем `position`

Разбор строки не возвращает коды ошибок и не печатает сообщения сам. При первой же ошибке бросается
`TimesheetFormatException` (наследник `IllegalArgumentException`): `position = 0` — ошибка структуры
(пустая строка, не 5 значений), `1..5` — номер некорректного значения. Благодаря этому:
- сообщение гарантированно содержит позицию («Позиция 3: ...»);
- `SelfCheck` проверяет позицию по полю, а не разбором текста;
- `report(String)` в одном месте превращает исключение в «ОШИБКА: ...».

## Принятые допущения (где правило допускает толкование)

- Пробелы вокруг значения игнорируются (`trim`), знак `+` и дробные числа не допускаются, `-1` — ошибка диапазона.
- Хвостовая `;` даёт шестой (пустой) элемент, поэтому строка некорректна (`split(";", -1)`).
- Повторяющиеся значения допустимы. Если ошибок несколько, сообщается первая по порядку позиций.
- В варианте 5 значение 17 допустимо (граница 30); ошибка начинается с 31.
- Stream API не используется.
